# P9：补充材料与增量分析闭环 实施计划

## Context

P0–P7 已完成：尽调任务主链路、证据中心、计划生成、Graph 编排执行与持久化、12 个 Agent、报告版本与人工复核留痕。
但当前仍存在三处断点：

1. Agent 产出的 `findings` / `supplementRequests` 只存在于 `dd_agent_execution.result_content`（JSON 快照），无法按 Agent / 分类 / 严重程度 / 状态检索，也无法给客户经理形成待办。
2. 计划与证据溯源缺少查询接口：前端拿不到当前计划、历史计划版本，也无法从一条证据反查引用它的线索、报告与复核记录。
3. 任务状态机在 `ANALYZING` 之后没有自动推进；补充材料完成后也无法触发增量重分析，报告定稿后任务不会置为 `COMPLETED`。

P9 目标：补齐上述闭环，**不做** Word/PDF 导出、真实银行接口、Agent 接大模型。

### 第 3 步：状态闭环

- `TaskStateMachine` 增加 `REANALYZING -> WAITING_FOR_SUPPLEMENT`（现有 `ANALYZING/REANALYZING -> RISK_ASSESSING -> REPORT_GENERATING -> WAITING_FOR_REVIEW` 已存在）。
- `DdTaskService` + impl 新增（均用条件更新 + `version+1` + SSE 推送，风格对齐 `markAnalyzing`）：
  - `markRiskAssessing`、`markReportGenerating`、`markWaitingForReview`、`markWaitingForSupplement`（严格流转，冲突抛 `230103`）
  - `beginReanalyzing`（`WAITING_FOR_SUPPLEMENT` 或 `RETURNED` → `REANALYZING`，不符返回 false）
  - `markCompletedIfWaitingForReview`、`markReturnedIfWaitingForReview`（返回 boolean，不抛异常，供报告复核联动，避免把报告测试与任务状态强耦合）
- `DdPlanScheduler.schedule` 在 Graph 成功后：有待处理补充资料 → `ANALYZING -> WAITING_FOR_SUPPLEMENT`；否则 `ANALYZING -> RISK_ASSESSING -> REPORT_GENERATING -> WAITING_FOR_REVIEW`。待处理数量通过 `DdSupplementRequestMapper` 直接统计（与现有 `DdPlanMapper` 直接注入保持一致，避免 service 循环依赖）。
- `DdReportServiceImpl.review` 复核联动：`FINALIZE` → `markCompletedIfWaitingForReview`；`REJECT/REQUEST_MATERIAL` → `markReturnedIfWaitingForReview`；`REANALYZE` → 任务处于 `RETURNED` 时 `beginReanalyzing` 并触发全量重分析（见第 4 步方法）。

### 第 4 步：补充材料完成后增量重分析

- [GraphExecutor](file:///D:/code/omni-bank/omni-bank-service/omni-bank-service-agent/omni-bank-service-agent-boot/src/main/java/com/omnibank/service/agent/dd/graph/GraphExecutor.java) 增加重载 `execute(definition, taskId, planId, Set<String> rerunAgents)`：
  - `null` = 全量执行；`Set.of()` = 全部复用（等价现有 resume=true）；非空 = 仅这些 Agent 对应节点不复用，其余复用。
  - 现有 `execute(..., boolean resume)` 委托到新重载，行为不变（现有 67 个测试不受影响）。
- `DdPlanScheduler.reanalyze(taskId, impactedAgents)`：
  1. 校验任务处于 `WAITING_FOR_SUPPLEMENT` / `RETURNED`，取当前计划；
  2. 用 `plan.agentPlan` + `plan.dependencyPlan` 计算受影响 Agent 的**下游闭包**（自身 + 所有传递依赖它的 Agent）；
  3. `beginReanalyzing` → `graphExecutor.execute(definition, taskId, planId, closure)`；
  4. 报告 Agent 在闭包内会调用 `report.createReportVersion` 自动生成新版本；
  5. 复用第 3 步的推进逻辑回到 `WAITING_FOR_SUPPLEMENT` 或 `RISK_ASSESSING -> REPORT_GENERATING -> WAITING_FOR_REVIEW`；
  6. 失败走 `markFailed`，保持与 `resume` 一致。
- `DdSupplementRequestServiceImpl.complete(...)`：状态置 `COMPLETED` + 记录 remark/completedAt，随后调用 `DdPlanScheduler.reanalyze`，受影响 Agent 取该请求的 `agentCode`（为空则全量重分析）。
