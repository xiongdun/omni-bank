# 接口契约规范（API Contract Specification）

- 文档版本：V1.0
- 文档性质：前后端接口契约 + 后端内部接口契约 + Agent/Tool 接口规范
- 适用范围：整个项目

# 1. 接口设计总则

## 1.1 接口体系

系统接口分为四类：

| 接口类别 | 调用方 | 被调用方 | 主要职责 |
|---|---|---|---|
| 前后端 REST API | Vue 前端 | Spring Boot 后端 | 任务、企业、材料、报告等业务操作 |
| 内部 Application API | 业务服务 | Domain/Application | 业务用例编排 |
| Agent Tool API | Agent | Tool Registry | 获取数据、执行计算、调用外部能力 |
| Adapter API | Tool | 行内系统/外部平台 | 屏蔽第三方接口差异 |

整体调用关系：

```text
Vue Frontend
     |
     | HTTP REST
     v
API Controller
     |
     v
Application Service
     |
     +-------------------+
     |                   |
     v                   v
Domain Service       Agent Graph
                         |
                         v
                    Professional Agent
                         |
                         v
                    Tool Registry
                         |
                         v
                      Adapter
                         |
             +-----------+-----------+
             |           |           |
             v           v           v
           CRM        信贷系统      外部数据
```

## 1.2 命名规范

REST API 统一采用：

- URL 使用小写字母。
- 多单词使用连字符或统一的资源命名方式。
- URL 使用复数资源名。
- JSON 字段统一采用 camelCase。
- Java 类名使用 PascalCase。
- 枚举使用大写下划线形式。
- 日期使用 ISO 8601 格式。
- 金额使用 Decimal 类型，不允许使用浮点数进行金额计算。

统一 API 前缀：

`/api/v1`

## 1.3 统一响应格式

所有 REST API 使用统一响应结构。

```json
{
  "code": "000000",
  "msg": "success",
  "data": {},
  "traceId": "trace-20261031-001",
  "timestamp": "2026-10-31T10:00:00+08:00"
}
```

字段定义：

| 字段 | 类型 | 说明 |
|---|---|---|
| code | String | 业务响应码 |
| msg | String | 响应描述 |
| data | Object | 业务响应数据 |
| traceId | String | 全链路追踪 ID |
| timestamp | String | 响应时间 |

成功响应：

`code = 000000`

失败响应：

使用统一错误码体系。

### 统一错误码

| 错误码 | 含义 |
|---|---|
| 000000 | 成功 |
| 400001 | 请求参数错误 |
| 400002 | 企业主体标识缺失 |
| 400003 | 业务场景无法识别 |
| 400004 | 任务状态不允许当前操作 |
| 400005 | 文件类型不支持 |
| 400006 | 文件大小超限 |
| 400007 | 文件内容校验失败 |
| 400008 | 证据不存在 |
| 400009 | Agent 不存在 |
| 400010 | Agent 当前不可执行 |
| 400011 | 数据版本冲突 |
| 400012 | 人工确认信息不完整 |
| 401001 | 未授权 |
| 403001 | 无权执行当前操作 |
| 404001 | 任务不存在 |
| 404002 | 企业不存在 |
| 404003 | 文件不存在 |
| 404004 | 计划不存在 |
| 409001 | 幂等请求重复 |
| 409002 | 任务正在执行 |
| 429001 | 请求频率超限 |
| 500001 | 系统内部异常 |
| 500002 | 外部接口调用失败 |
| 500003 | 模型调用失败 |
| 500004 | Agent 执行失败 |
| 500005 | 文件存储失败 |
| 500006 | 数据处理失败 |

具体错误码可以扩展，但不得在不同模块中随意重复定义。

# 2. 尽调任务接口

## 2.1 创建尽调任务

`POST /api/v1/dd/tasks`

请求：

```json
{
  "enterprise": {
    "enterpriseName": "江西某某科技有限公司",
    "unifiedSocialCreditCode": "913600000000000000",
    "bankCustomerId": "CUST000001"
  },
  "creditApplication": {
    "creditApplicationId": "APP2026100001",
    "productCode": "CORPORATE_WORKING_CAPITAL",
    "productName": "流动资金贷款",
    "applicationAmount": "5000000.00",
    "currency": "CNY",
    "applicationTerm": 12,
    "termUnit": "MONTH",
    "loanPurpose": "采购原材料"
  },
  "source": "MANUAL",
  "attachmentIds": []
}
```

字段要求：

| 字段 | 必填 | 说明 |
|---|---|---|
| enterprise.enterpriseName | 否 | 企业名称 |
| enterprise.unifiedSocialCreditCode | 否 | 统一社会信用代码 |
| enterprise.bankCustomerId | 否 | 行内客户编号 |
| creditApplication.creditApplicationId | 否 | 授信申请编号 |
| creditApplication.productCode | 否 | 产品编号 |
| creditApplication.applicationAmount | 否 | 申请金额 |
| creditApplication.applicationTerm | 否 | 申请期限 |
| creditApplication.loanPurpose | 否 | 贷款用途 |
| source | 是 | 创建来源 |

企业名称、统一社会信用代码、行内客户编号至少提供一种主体识别信息。

金额必须使用字符串传输，后端转换为 BigDecimal。

响应：

```json
{
  "code": "000000",
  "msg": "success",
  "data": {
    "taskId": "DD202610310001",
    "taskStatus": "CREATED",
    "enterpriseId": "ENT000001",
    "createdAt": "2026-10-31T10:00:00+08:00"
  }
}
```

业务要求：

1. 创建任务时生成全局唯一 taskId。
2. 企业主体和授信申请信息分别建立上下文。
3. 如果传入授信申请编号，后端允许异步获取申请信息。
4. 不得因某个非必需字段缺失而拒绝创建任务。
5. 创建接口必须支持幂等控制。
6. 创建任务后由任务编排服务启动初始化流程。
7. 首期 Mock 数据必须标记 isMock。

# 4. 材料上传接口

## 4.1 上传材料

`POST /api/v1/dd/tasks/{taskId}/documents`

Content-Type：

`multipart/form-data`

参数：

- file：文件。
- documentCategory：材料类别。
- description：材料说明。
- isMock：是否为模拟材料。

响应：

```json
{
  "code": "000000",
  "msg": "success",
  "data": {
    "documentId": "DOC000001",
    "fileName": "企业财务报表.pdf",
    "documentCategory": "FINANCIAL_STATEMENT",
    "uploadStatus": "SUCCESS",
    "parseStatus": "PENDING",
    "evidenceIds": [
      "EV000001"
    ]
  }
}
```

要求：

- 文件存储使用 MinIO。
- 文件元数据通过业务服务保存。
- 计算 SHA-256。
- 支持文件重复检测。
- 不允许上传路径穿越、伪造扩展名或不符合白名单的文件。
- 需要预留病毒扫描。
- 上传失败不能留下错误的成功记录。

## 4.2 查询材料列表

`GET /api/v1/dd/tasks/{taskId}/documents`

支持：

- documentCategory
- uploadStatus
- parseStatus
- page
- pageSize

## 4.3 删除材料

`DELETE /api/v1/dd/tasks/{taskId}/documents/{documentId}`

要求：

- 仅允许删除尚未被正式分析引用的材料，或通过受控撤销机制处理。
- 不允许物理删除已被 Agent 结果引用的原始证据。
- 撤销操作保留审计记录。
- 已经生成的分析结果需要标记为可能受到证据变化影响。

# 9. 工具调用内部契约

## 9.1 Tool 统一接口

```java
public interface DomainTool<I, O> {

    ToolDefinition getDefinition();

    ToolResult<O> execute(ToolRequest<I> request);

}
```

实际工程中需要根据是否为耗时操作提供异步执行能力，不能要求所有工具都同步等待。

## 9.2 ToolRequest

```java
public class ToolRequest<T> {

    private String requestId;

    private String taskId;

    private String executionId;

    private String idempotencyKey;

    private String enterpriseId;

    private T parameters;

    private Map<String, Object> context;

}
```

## 9.3 ToolResult

```java
public class ToolResult<T> {

    private boolean success;

    private String status;

    private T data;

    private String source;

    private LocalDateTime queryTime;

    private List<String> evidenceIds;

    private String errorCode;

    private String errormsg;

    private boolean mock;

}
```

status：

- SUCCESS
- PARTIAL_SUCCESS
- NOT_FOUND
- UNAVAILABLE
- TIMEOUT
- FAILED
- PENDING
- NEEDS_AUTHORIZATION

## 9.4 Adapter 统一接口

```java
public interface EnterpriseInfoAdapter {

    AdapterResult<EnterpriseProfileDTO> queryEnterprise(
        EnterpriseQueryRequest request
    );

}
```

所有真实银行接口必须通过 Adapter 实现。

禁止在 Agent 中直接调用第三方 HTTP 地址。

## 9.5 Tool 安全约束

Tool 分为：

1. QUERY：查询工具。
2. ANALYSIS：分析工具。
3. CALCULATION：计算工具。
4. OPERATION：操作工具。

LLM 可以根据上下文选择授权范围内的查询工具。

# 13. 接口异常处理

## 13.1 外部接口超时

不能将外部系统超时直接转换成企业无风险或无数据。

应返回：

`UNAVAILABLE` 或 `TIMEOUT`

并将该数据标记为未获取。

## 13.2 部分成功

例如：

工商数据成功，CRM 超时。

应保留工商数据，CRM 标记未获取，继续其他可执行流程。

## 13.3 模型异常

模型服务超时或输出格式错误：

1. 按配置执行有限次数重试。
2. 结构化输出校验。
3. 不符合 Schema 时允许修复重试。
4. 超出重试次数后标记 FAILED。
5. 保存模型异常和 Prompt 版本。
6. 不得将异常结果作为有效分析结果。

## 13.4 数据冲突

多来源字段不一致：

- 保留所有来源。
- 生成冲突记录。
- 关联 Evidence。
- 交给相关 Agent 或人工复核。
- 不允许静默覆盖。
